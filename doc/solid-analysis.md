## O — Open/Closed Principle

- [`ScoringStrategy.java:4`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/ScoringStrategy.java#L4) กำหนด `key()`/`score(ScoringInput)`; [`CourseMatcherService.java:41`](../code/backend/src/main/java/com/example/courserecommend/matcher/CourseMatcherService.java#L41) รับ `List<ScoringStrategy>` ทาง constructor และ [`CourseMatcherService.java:47`](../code/backend/src/main/java/com/example/courserecommend/matcher/CourseMatcherService.java#L47) ตรวจ key ไม่ซ้ำก่อนเรียงลำดับ. [`CourseMatcherService.java:98`](../code/backend/src/main/java/com/example/courserecommend/matcher/CourseMatcherService.java#L98) เรียกทุก strategy โดยไม่ switch ชนิด concrete. เพิ่มวิธีคิดคะแนนใหม่ได้ด้วย implementation ของ interface และ bean ใหม่ โดยไม่แก้ loop จัดอันดับ.
- ตัวอย่าง extension ที่มีจริง: [`BudgetFitStrategy.java:9`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/BudgetFitStrategy.java#L9), [`EffortFitStrategy.java:7`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/EffortFitStrategy.java#L7), [`ReviewQualityStrategy.java:9`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/ReviewQualityStrategy.java#L9). หลักฐาน: [`CourseMatcherServiceTests.java:35`](../test/backend/unit/com/example/courserecommend/matcher/CourseMatcherServiceTests.java#L35) สร้าง service ด้วยทั้งสาม implementation และตรวจลำดับ breakdown, top 3, hard filter.

## L — Liskov Substitution Principle

- **Contract ก่อนแทนที่:** [`ScoringInput.java:13`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/ScoringInput.java#L13) บังคับราคา THB ที่ทราบและไม่เกินงบ, ชั่วโมงในช่วง 1–168, effort เป็นบวกเมื่อมีค่า, rating/count สอดคล้องกัน; input นี้สร้างหลัง [`EligibilityPolicy.java:16`](../code/backend/src/main/java/com/example/courserecommend/matcher/EligibilityPolicy.java#L16) กรอง hard constraints. [`ScoringStrategy.java:4`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/ScoringStrategy.java#L4) ให้ทุก implementation รับ input แบบเดียวกัน. [`ScoringResult.java:6`](../code/backend/src/main/java/com/example/courserecommend/matcher/scoring/ScoringResult.java#L6) ปฏิเสธ key ว่าง, score ไม่ finite/นอก 0–100 และ reason ว่าง; matcher ใช้ key, score และ reason เหมือนกันทุกตัว.
- **การแทนกันได้จริง:** [`CourseMatcherService.java:98`](../code/backend/src/main/java/com/example/courserecommend/matcher/CourseMatcherService.java#L98) เรียก `strategy.score(input)` ใน loop เดียว แล้วเฉลี่ยผลโดยไม่ตรวจ concrete type. [`ScoringStrategyContractTests.java:23`](../test/backend/unit/com/example/courserecommend/matcher/ScoringStrategyContractTests.java#L23) parameterize `BudgetFitStrategy`, `EffortFitStrategy`, `ReviewQualityStrategy` บนชุด input เดียวกัน และยืนยัน deterministic result, key ตรง strategy, คะแนน finite 0–100, reason มีข้อมูล. [`ScoringStrategyContractTests.java:70`](../test/backend/unit/com/example/courserecommend/matcher/ScoringStrategyContractTests.java#L70) ทดสอบการปฏิเสธ input/output ผิด contract. จึงมีหลักฐานมากกว่าเพียงการ `implements` interface.
- ขอบเขต contract คือ **eligible snapshot** เท่านั้น; เช่น budget strategy ต้องไม่รับ paid course ที่ราคาเกินงบ. ไม่มีข้อสรุปว่า implementation ใช้แทนกันได้บน input ที่ฝ่าฝืน precondition.

## I — Interface Segregation Principle

- [`CourseQueryService.java:10`](../code/backend/src/main/java/com/example/courserecommend/course/CourseQueryService.java#L10) แยก `getCourse`/`listCoursesByProvider`; [`CourseCommandService.java:10`](../code/backend/src/main/java/com/example/courserecommend/course/CourseCommandService.java#L10) แยก create/update/submit/delete. [`CourseController.java:20`](../code/backend/src/main/java/com/example/courserecommend/course/CourseController.java#L20) ระบุ dependency สอง interface ตามการใช้งาน; [`CourseServiceImpl.java:35`](../code/backend/src/main/java/com/example/courserecommend/course/CourseServiceImpl.java#L35) implement ทั้งคู่. ผู้ใช้ที่ต้องอ่านอย่างเดียวสามารถขึ้นกับ query contract โดยไม่ต้องรับ mutation contract.
- หลักฐาน: [`CourseControllerTests.java:67`](../test/backend/unit/com/example/courserecommend/course/CourseControllerTests.java#L67) เป็นต้นไปทดสอบ endpoint การอ่าน/เขียนและสิทธิ์; `CourseServiceTests`/`CourseServiceImplMockitoTests` ตรวจพฤติกรรมของ implementation. การแยก interface ยังไม่ได้แยก runtime class หรือ transaction boundary ซึ่งไม่ใช่ข้อสรุปของหลักนี้.

## D — Dependency Inversion Principle

- [`ProviderController.java:30`](../code/backend/src/main/java/com/example/courserecommend/provider/ProviderController.java#L30) ขึ้นกับ [`ProviderService.java:13`](../code/backend/src/main/java/com/example/courserecommend/provider/ProviderService.java#L13) แทน concrete [`ProviderServiceImpl.java:31`](../code/backend/src/main/java/com/example/courserecommend/provider/ProviderServiceImpl.java#L31). Course controller ขึ้นกับ query/command interfaces ที่บรรทัด 20–21 ข้างต้น. Spring constructor injection ผูก implementation ที่ runtime.
- ฝั่ง moderation, [`CourseModerationServiceImpl.java:30`](../code/backend/src/main/java/com/example/courserecommend/course/CourseModerationServiceImpl.java#L30) ขึ้นกับ [`AdminActorResolver.java:5`](../code/backend/src/main/java/com/example/courserecommend/security/AdminActorResolver.java#L5); [`SecurityContextAdminActorResolver.java:14`](../code/backend/src/main/java/com/example/courserecommend/security/SecurityContextAdminActorResolver.java#L14) เป็น implementation ที่อ่าน security context. หลักฐาน: `ProviderControllerTests`, `CourseControllerTests`, `AdminModerationControllerTests` รันผ่านกับ wiring จริง; [`CourseMatcherServiceTests.java:25`](../test/backend/unit/com/example/courserecommend/matcher/CourseMatcherServiceTests.java#L25) ฉีด repository mocks และ strategy implementations เข้า constructor ได้โดยไม่แก้ service.
- ขอบเขต: บาง service ยังขึ้นกับ concrete helper/service เช่น `CatalogCourseService`; จึงอ้าง DIP สำหรับ boundary ที่ระบุไว้ ไม่เหมารวมทั้งระบบ.

## 1. กลุ่มผู้เรียน (Learner Use Cases)

### UC01: ค้นหา กรอง และเปรียบเทียบคอร์ส (Search & Filter Courses)
- **Actor:** ผู้เรียน (Learner - สมาชิก หรือ บุคคลทั่วไป)
- **คำอธิบาย:** ผู้เรียนสามารถค้นหาคอร์สด้วยคำค้น (Keyword) พร้อมทั้งกรองตามหมวดหมู่, ระดับความยาก, ภาษา, ช่วงราคา และจัดเรียงข้อมูลได้
- **เงื่อนไขเริ่มต้น (Preconditions):** ไม่มี (บุคคลทั่วไปเข้าถึงได้)
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนเข้าสู่หน้าค้นหาคอร์ส (Course Catalog)
  2. ผู้เรียนป้อนคำค้นหา หรือเลือกตัวกรอง (เช่น หมวดหมู่ Web Development, ระดับ Beginner, ราคาฟรี)
  3. ระบบประมวลผลคำขอ ส่งต่อไปยัง Backend API `/api/v1/courses` พร้อม Query Parameters
  4. Backend ส่งรายการคอร์สแบบแบ่งหน้า (Pagination) และข้อมูลการเรียงลำดับกลับมา
  5. ระบบแสดงผลรายการคอร์สที่ตรงตามเงื่อนไข พร้อมข้อมูลคะแนนรีวิวเฉลี่ยและราคาปัจจุบัน
- **ขั้นตอนทางเลือก (Alternative Flow):**
  - หากไม่พบข้อมูลที่ตรงตามเงื่อนไข ระบบจะแสดงข้อความแจ้งว่า "ไม่พบคอร์สที่ตรงกับเงื่อนไขการค้นหา" พร้อมปุ่มล้างตัวกรอง

### UC02: ทำแบบทดสอบ Matcher แนะนำคอร์ส (Course Matcher Quiz)
- **Actor:** ผู้เรียน (Learner)
- **คำอธิบาย:** ระบบถามตอบสั้น ๆ 4 มิติเพื่อจับคู่และจัดอันดับคอร์สที่เหมาะสมกับผู้เรียนที่สุด โดยอาศัย Strategy Pattern ในการคิดคะแนน
- **เงื่อนไขเริ่มต้น (Preconditions):** มีคอร์สสถานะ Published อยู่ในระบบ
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนเข้าสู่หน้า Course Matcher และตอบคำถามสั้น 4 ส่วน (เป้าหมายสายอาชีพ, ระดับพื้นฐาน, งบประมาณ, เวลาเรียนต่อสัปดาห์)
  2. ผู้เรียนกดยืนยันคำตอบ ระบบส่งข้อมูลแบบสอบถามไปยัง `/api/v1/course-matches`
  3. Service คัดกรองคอร์สเบื้องต้น (Hard Filter เช่น ภาษาและระดับ) จากนั้นนำคอร์สที่ผ่านเกณฑ์เข้าสู่ Scoring Strategy คำนวณน้ำหนักคะแนน
  4. ระบบส่งคืนรายการคอร์สที่เหมาะสมที่สุดไม่เกิน 3 อันดับ พร้อมแสดง "เหตุผลประกอบการแนะนำ" ที่ตรวจสอบได้
- **ขั้นตอนทางเลือก (Alternative Flow):**
  - หากไม่มีคอร์สที่ผ่านเงื่อนไข ระบบจะแสดงคอร์สที่ใกล้เคียงที่สุดพร้อมระบุเงื่อนไขที่เป็นข้อจำกัด (เช่น งบประมาณจำกัดเกินไป)

### UC03: ดู Roadmap เส้นทางการเรียนรู้สายอาชีพ (View Career Roadmap)
- **Actor:** ผู้เรียน (Learner)
- **คำอธิบาย:** ผู้เรียนเปิดดูแผนที่เส้นทางการเรียนรู้ตามสายอาชีพ (เช่น Frontend Developer, Data Analyst) เพื่อดูขั้นตอนและคอร์สแนะนำในแต่ละขั้น
- **เงื่อนไขเริ่มต้น (Preconditions):** ไม่มี
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนเลือกสายอาชีพที่สนใจในหน้า Roadmap
  2. ระบบแสดงแผนภาพขั้นตอนการเรียนรู้ตั้งแต่พื้นฐานจนถึงขั้นประยุกต์
  3. ในแต่ละขั้นตอน ผู้เรียนสามารถคลิกดูคอร์สทางเลือกที่ตรงกับเนื้อหาในขั้นนั้นๆ ได้

---

### UC04: สมัครสมาชิกและเข้าสู่ระบบ (Sign Up / Sign In)
- **Actor:** ผู้ใช้งานทั่วไป (Guest) / ผู้เรียน (Learner)
- **คำอธิบาย:** การสร้างบัญชีผู้ใช้งานใหม่ และการยืนยันตัวตนเข้าสู่ระบบผ่าน Spring Security Session Cookie
- **เงื่อนไขเริ่มต้น (Preconditions):** ผู้ใช้งานยังไม่ได้เข้าสู่ระบบ
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ใช้งานกรอกอีเมลและรหัสผ่านที่หน้าเข้าสู่ระบบ/สมัครสมาชิก
  2. ระบบตรวจสอบความถูกต้องของฟอร์ม (Form Validation) และส่งคำขอไปยัง `/api/v1/auth/register` หรือ `/api/v1/auth/login`
  3. Backend ตรวจสอบรหัสผ่านด้วย Password Encoder (BCrypt)
  4. Backend สร้าง Session และแนบ `Set-Cookie` แบบ HttpOnly/SameSite กลับมาให้เบราว์เซอร์
  5. ระบบเปลี่ยนสถานะหน้าเว็บเป็นล็อกอินแล้ว และดึงข้อมูลโปรไฟล์ผู้ใช้มาแสดง
- **ขั้นตอนผิดพลาด (Exception Flow):**
  - หากอีเมลซ้ำ หรือรหัสผ่านไม่ถูกต้อง ระบบจะตอบกลับด้วยรหัส 400 หรือ 401 พร้อมข้อความแจ้งเตือนข้อผิดพลาด

---

### UC05: จัดการโปรไฟล์ส่วนตัว (Manage Profile)
- **Actor:** ผู้เรียน (Learner - ล็อกอินแล้ว)
- **คำอธิบาย:** ปรับปรุงข้อมูลส่วนตัว เช่น ชื่อที่แสดง (Display Name), ประวัติย่อ (Bio) และรูปประจำตัว
- **เงื่อนไขเริ่มต้น (Preconditions):** เข้าสู่ระบบเรียบร้อยแล้ว
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนเข้าสู่หน้า "โปรไฟล์ของฉัน" (`/api/v1/me/profile`)
  2. ปรับแก้ข้อมูลชื่อหรือประวัติย่อ แล้วกดยืนยันบันทึก
  3. ข้อมูลถูกบันทึกอัปเดตลงตาราง `user_profiles` ซึ่งเชื่อมโยงแบบ One-to-One กับบัญชีผู้ใช้

---

### UC06: บันทึกคอร์สที่สนใจ (Bookmark / Saved Courses)
- **Actor:** ผู้เรียน (Learner - ล็อกอินแล้ว)
- **คำอธิบาย:** บันทึกคอร์สเรียนที่สนใจเก็บไว้ในรายการส่วนตัว หรือกดยกเลิกการบันทึก
- **เงื่อนไขเริ่มต้น (Preconditions):** เข้าสู่ระบบเรียบร้อยแล้ว
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนกดปุ่ม "บันทึกคอร์ส" ที่การ์ดหรือหน้ารายละเอียดคอร์ส
  2. ระบบส่งคำขอ POST ไปยัง `/api/v1/me/saved-courses/{courseId}`
  3. Backend บันทึกความสัมพันธ์ลงตาราง `saved_courses`
  4. ผู้เรียนสามารถเปิดดูรายการคอร์สที่บันทึกไว้ทั้งหมดได้ที่หน้าส่วนตัว (`/api/v1/me/saved-courses`)

---

### UC07: เขียนรีวิวและให้คะแนน 3 มิติ (Write Review)
- **Actor:** ผู้เรียน (Learner - ล็อกอินแล้ว)
- **คำอธิบาย:** เขียนรีวิวและให้คะแนนคอร์สเรียน โดยแบ่งการให้คะแนนออกเป็น 3 ด้าน พร้อมคะแนนภาพรวม (จำกัด 1 บัญชีต่อ 1 รีวิวต่อคอร์ส)
- **เงื่อนไขเริ่มต้น (Preconditions):** เข้าสู่ระบบแล้ว และยังไม่เคยเขียนรีวิวคอร์สนี้มาก่อน
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนเปิดหน้ารายละเอียดคอร์ส แล้วกดปุ่ม "เขียนรีวิว"
  2. ผู้เรียนกรอกคะแนน (1-5 ดาว) ในแต่ละด้าน:
     - คุณค่าของเนื้อหา (Content Score)
     - คุณภาพการสอน (Teaching Score)
     - ความตรงตามระดับความยาก (Difficulty Match Score)
     - คะแนนภาพรวม (Overall Score)
     - ข้อความรีวิว (Review Body)
  3. ระบบส่งคำขอ POST `/api/v1/courses/{id}/reviews`
  4. รีวิวถูกบันทึกลงฐานข้อมูลในสถานะ `PENDING` เพื่อรอผู้ดูแลระบบตรวจคัดกรองก่อนแสดงสาธารณะ

---

### UC08: กดลิงก์ออกไปเรียนที่เว็บต้นทาง (Outbound Link)
- **Actor:** ผู้เรียน (Learner)
- **คำอธิบาย:** นำทางผู้เรียนไปยังเว็บไซต์ต้นทางของผู้ให้บริการคอร์ส (เช่น Udemy, Coursera, สถาบัน) โดยระบบจะตรวจสอบความปลอดภัยของ URL ก่อน
- **เงื่อนไขเริ่มต้น (Preconditions):** คอร์สมีสถานะเป็น Published
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้เรียนกดปุ่ม "ไปที่หน้าคอร์สเรียน" ในหน้ารายละเอียดคอร์ส
  2. ระบบเรียก GET `/api/v1/courses/{id}/outbound-link` เพื่อรับ URL ปลายทางที่ผ่านการตรวจสอบ Host Allowlist แล้ว
  3. ระบบบันทึกสถิติจำนวนการคลิก (Click Count) เพื่อวิเคราะห์ความสนใจ
  4. เบราว์เซอร์เปิดหน้าต่างใหม่ไปยังเว็บไซต์ต้นทางอย่างปลอดภัย

## 2. กลุ่มผู้ให้บริการคอร์ส (Provider Use Cases)

### UC09: สมัครเปิดบัญชีผู้ให้บริการ (Provider Registration)
- **Actor:** สถาบันหรือผู้สอน (Provider)
- **คำอธิบาย:** ยื่นคำขอเปิดบัญชีสถาบัน/ผู้ให้บริการ เพื่อนำคอร์สมาลงบนแพลตฟอร์ม
- **เงื่อนไขเริ่มต้น (Preconditions):** เข้าสู่ระบบด้วยบัญชีผู้ใช้ทั่วไปเรียบร้อยแล้ว
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ใช้กรอกแบบฟอร์มขอเป็นผู้ให้บริการ (ชื่อสถาบัน, รายละเอียด, ลิงก์เว็บไซต์ และ URL Slug ที่ต้องการ)
  2. ระบบตรวจสอบความไม่ซ้ำกันของ Slug แล้วส่งคำขอไปที่ `/api/v1/providers`
  3. ระบบบันทึกข้อมูลในสถานะ `PENDING` และกำหนดให้ผู้ยื่นคำขอเป็นสมาชิกตำแหน่ง `OWNER`
  4. รอการตรวจสอบอนุมัติจาก Admin

---

### UC10: จัดการข้อมูลโปรไฟล์สถาบัน และ URL Slug (Manage Provider Profile)
- **Actor:** เจ้าของสถาบัน (Provider Owner / Editor)
- **คำอธิบาย:** แก้ไขข้อมูลสาธารณะของสถาบัน เช่น โลโก้ คำอธิบายเว็บไซต์ และช่องทางการติดต่อ
- **เงื่อนไขเริ่มต้น (Preconditions):** เป็นสมาชิกของ Provider ที่มีสิทธิ์ตามระบบ (Owner หรือ Editor)
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ให้บริการแก้ไขข้อมูลในหน้าแดชบอร์ดสถาบัน
  2. ระบบส่งคำขอ PUT `/api/v1/providers/{id}`
  3. Service ตรวจสอบสิทธิ์ความเป็นเจ้าของ (Ownership Verification) ก่อนอนุญาตให้บันทึกข้อมูล

---

### UC11: จัดการสมาชิกในทีม (Manage Team Members: Owner/Editor)
- **Actor:** เจ้าของสถาบัน (Provider Owner เท่านั้น)
- **คำอธิบาย:** เพิ่มหรือถอดถอนสมาชิกในทีมผู้ให้บริการ พร้อมกำหนดบทบาทสิทธิ์ (Owner หรือ Editor)
- **เงื่อนไขเริ่มต้น (Preconditions):** ต้องมีบทบาทเป็น `OWNER` ของ Provider นั้นๆ
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Owner ระบุอีเมลของผู้ใช้ที่ต้องการเพิ่มเข้าทีม พร้อมเลือกบทบาท (`EDITOR` หรือ `OWNER`)
  2. ส่งคำขอ POST `/api/v1/providers/{id}/members`
  3. ระบบบันทึกความสัมพันธ์ลงตาราง `provider_members`

---

### UC12: สร้างและแก้ไขคอร์สเรียนแบบร่าง (Create/Edit Course Draft)
- **Actor:** สมาชิกผู้ให้บริการ (Owner หรือ Editor)
- **คำอธิบาย:** สร้างข้อมูลคอร์สใหม่ในสถานะแบบร่าง (`DRAFT`) หรือแก้ไขข้อมูลคอร์สที่มีอยู่
- **เงื่อนไขเริ่มต้น (Preconditions):** เป็นสมาชิกที่มีสิทธิ์ของ Provider
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ให้บริการกรอกข้อมูลคอร์ส: ชื่อคอร์ส, คำอธิบาย, ลิงก์ต้นทาง, แพลตฟอร์ม, ระดับความยาก, ภาษา, ระยะเวลาเรียน และราคา
  2. ระบบส่งคำขอ POST `/api/v1/providers/{providerId}/courses`
  3. คอร์สถูกบันทึกในสถานะ `DRAFT` พร้อมผูกข้อมูลราคาลงตาราง `course_prices`

---

### UC13: ส่งคอร์สเข้าคิวตรวจสอบ (Submit Course for Moderation)
- **Actor:** สมาชิกผู้ให้บริการ (Owner หรือ Editor)
- **คำอธิบาย:** ยื่นส่งคอร์สที่เตรียมข้อมูลเรียบร้อยแล้วเข้าสู่คิวการตรวจสอบของทีมงาน Admin
- **เงื่อนไขเริ่มต้น (Preconditions):** คอร์สอยู่ในสถานะ `DRAFT` หรือ `REVISION_REQUESTED`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ให้บริการกดปุ่ม "ส่งตรวจคอร์ส" (Submit)
  2. ระบบส่งคำขอ POST `/api/v1/courses/{id}/submissions`
  3. คลาส State Pattern (`DraftState`) ตรวจสอบความสมบูรณ์และสั่งเปลี่ยนสถานะเป็น `PENDING`
  4. ระบบบันทึกประวัติการส่งลงใน `audit_logs`

---

### UC14: ลบคอร์ส (Delete Course)
- **Actor:** สมาชิกผู้ให้บริการ (Owner หรือ Editor)
- **คำอธิบาย:** ลบข้อมูลคอร์สออกจากระบบ (อนุญาตเฉพาะคอร์สที่เป็นแบบร่างและยังไม่มีประวัติการเผยแพร่เท่านั้น)
- **เงื่อนไขเริ่มต้น (Preconditions):** คอร์สต้องมีสถานะเป็น `DRAFT` เท่านั้น
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. ผู้ให้บริการกดยืนยันการลบคอร์ส
  2. ระบบส่งคำขอ DELETE `/api/v1/courses/{id}`
  3. Service ตรวจสอบว่าคอร์สเป็นสถานะ DRAFT จริง และไม่มีข้อมูลอ้างอิงสำคัญ (เช่น ไม่มีรีวิว)
  4. ระบบลบข้อมูลคอร์สและความสัมพันธ์ที่เกี่ยวข้อง (เช่น ราคา, หมวดหมู่) ใน Transaction เดียวกัน และตอบกลับด้วยรหัส 204 No Content
- **ขั้นตอนทางเลือก (Alternative Flow):**
  - หากคอร์สเคยเผยแพร่แล้ว (`PUBLISHED`) ระบบจะปฏิเสธคำขอลบด้วยรหัส 409 Conflict และแนะนำให้ใช้การระงับหรือเก็บถาวร (Archive) แทน

---

## 3. กลุ่มผู้ดูแลระบบ (Admin Use Cases)

### UC15: ตรวจสอบและอนุมัติคอร์ส (Course Moderation)
- **Actor:** ผู้ดูแลระบบ (Admin)
- **คำอธิบาย:** ตรวจสอบความถูกต้องของข้อมูลคอร์ส แล้วตัดสินใจ อนุมัติ (Publish), ขอให้แก้ไข (Request Revision) หรือสั่งพักการแสดงผล (Suspend)
- **เงื่อนไขเริ่มต้น (Preconditions):** บัญชีผู้ใช้มีบทบาทเป็น `ADMIN` และคอร์สอยู่ในสถานะ `PENDING`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Admin ตรวจสอบข้อมูลคอร์ส รายละเอียด ลิงก์ต้นทาง และราคา
  2. Admin เลือกคำตัดสิน (Approve / Request Revision พร้อมระบุหมายเหตุ)
  3. ระบบส่งคำขอ POST `/api/v1/admin/courses/{id}/moderation-decisions`
  4. คลาส State Pattern ประมวลผลการเปลี่ยนสถานะคอร์สเป็น `PUBLISHED` หรือ `REVISION_REQUESTED`
  5. ระบบบันทึกการกระทำและเหตุผลลง `audit_logs`
  6. Observer Pattern รับสัญญาณเหตุการณ์ `CourseStatusChangedEvent` เพื่ออัปเดตสถิติระบบ

---

### UC16: ตรวจสอบและรับรองผู้ให้บริการ (Verify Provider)
- **Actor:** ผู้ดูแลระบบ (Admin)
- **คำอธิบาย:** ตรวจสอบความน่าเชื่อถือของสถาบันหรือผู้สอนที่ยื่นขอเปิดบัญชี Provider
- **เงื่อนไขเริ่มต้น (Preconditions):** Provider มีสถานะเป็น `PENDING`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Admin ตรวจสอบเอกสาร/เว็บไซต์ของสถาบัน
  2. Admin กดปุ่มอนุมัติรับรอง (Verify)
  3. สถานะของ Provider เปลี่ยนเป็น `ACTIVE` ทำให้สถาบันสามารถส่งคอร์สเข้าตรวจสอบและเผยแพร่ได้

---

### UC17: ตรวจคัดกรองรีวิวและป้องกันสแปม (Moderate Reviews)
- **Actor:** ผู้ดูแลระบบ (Admin)
- **คำอธิบาย:** คัดกรองรีวิวจากผู้เรียนก่อนเปิดแสดงเป็นสาธารณะ เพื่อป้องกันคำหยาบคาย การสแปม หรือรีวิวเท็จ
- **เงื่อนไขเริ่มต้น (Preconditions):** รีวิวอยู่ในสถานะ `PENDING`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Admin เปิดหน้ารายการรีวิวรอตรวจสอบ
  2. Admin ตรวจสอบข้อความและกด "อนุมัติ" (Publish) หรือ "ปฏิเสธ" (Reject)
  3. สถานะรีวิวเปลี่ยนเป็น `PUBLISHED`
  4. คะแนนเฉลี่ยของคอร์สจะถูกคำนวณใหม่โดยนับเฉพาะรีวิวที่ได้รับการอนุมัติแล้วเท่านั้น

---

### UC18: จัดการหมวดหมู่และทักษะ (Taxonomy Management)
- **Actor:** ผู้ดูแลระบบ (Admin)
- **คำอธิบาย:** สร้าง แก้ไข หรือลบหมวดหมู่หลัก (Categories) และแท็กทักษะ (Skills/Tags) ของระบบ
- **เงื่อนไขเริ่มต้น (Preconditions):** บทบาท `ADMIN`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Admin เพิ่มชื่อหมวดหมู่ใหม่ เช่น "Data Science", "Cloud & DevOps"
  2. ระบบสร้าง Slug ภาษาอังกฤษ และบันทึกลงตาราง `categories`
  3. หมวดหมู่ใหม่จะปรากฏให้ผู้ให้บริการเลือกผูกกับคอร์ส และปรากฏในแถบตัวกรองของผู้เรียน

---

### UC19: ตรวจสอบประวัติการใช้งานระบบ (View System Audit Log)
- **Actor:** ผู้ดูแลระบบ (Admin)
- **คำอธิบาย:** เรียกดูประวัติการดำเนินกิจกรรมสำคัญในระบบ เช่น ใครเป็นผู้อนุมัติคอร์ส วันที่และเวลาที่มีการเปลี่ยนสถานะ
- **เงื่อนไขเริ่มต้น (Preconditions):** บทบาท `ADMIN`
- **ขั้นตอนการทำงานหลัก (Main Flow):**
  1. Admin เข้าสู่เมนู System Audit Logs
  2. Backend ดึงข้อมูลจากตาราง `audit_logs` พร้อมข้อมูลผู้กระทำ (Actor), ชนิดของข้อมูล (Entity Type), สถานะเดิม และสถานะใหม่
  3. ข้อมูลถูกแสดงผลแบบเรียงตามลำดับเวลาล่าสุด พร้อมตัวกรองตามประเภทกิจกรรม

## บัญชี UAT บน production — 10 ตุลาคม 2026 (Asia/Bangkok)

หลังได้รับอนุญาตจากผู้รับผิดชอบงาน สร้างบัญชีทดสอบ 3 บัญชีผ่าน `https://group36-coursehub.vercel.app/`: ผู้เรียน (user ID 8), เจ้าของ Provider (user ID 9) และบัญชีตรวจฟอร์มสมัครหน้าเว็บ (user ID 10) ทั้งหมดมี role `LEARNER` ตามระบบปัจจุบัน บัญชีที่สองสร้าง Provider ทดสอบ ID 7 ซึ่งตอนสร้างมีสถานะ `PENDING` และเห็นรายการนี้ผ่าน `/api/v1/providers/me` ส่วนบัญชีผู้เรียนไม่เห็น Provider ของอีกคน ต่อมามีการรับรอง Provider ทดสอบนี้แล้ว รอบตรวจล่าสุดเห็นสถานะ `ACTIVE`

สองบัญชีแรก login ตอบ 200, `/api/v1/me` ระบุบัญชีถูกต้อง, endpoint admin ตอบ 403, logout ตอบ 204 และ `/api/v1/me` หลัง logout ตอบ 401; session cookie มี `Secure`, `HttpOnly` และ `SameSite=Lax` ไม่บันทึกรหัสผ่านหรือค่า cookie ใน repo หลักฐานรหัสอยู่ในไฟล์ส่วนตัวบนเครื่องผู้รับผิดชอบงาน ซึ่งยังเป็นความเสี่ยงหากเจ้าของเครื่องไม่ว่าง ทีมควรย้ายสิทธิ์เข้าถึงบัญชีทดสอบไปที่ vault ของทีมก่อน UAT รอบถัดไป โดยไม่ส่งรหัสผ่านผ่าน PR บัญชีและ Provider ทดสอบยังคงอยู่สำหรับ UAT รอบถัดไป การลบ Provider ทำได้ผ่าน API โดยเจ้าของ แต่การลบบัญชีต้องประสานผู้ดูแลฐานข้อมูล เพราะยังไม่มี endpoint ลบบัญชี

## แผนเก็บกวาดข้อมูล UAT บน production

ก่อนเริ่ม UAT ที่สร้างข้อมูลเพิ่ม ต้องให้ทีมยืนยันผู้ดูแลฐาน Neon ที่ลงมือเก็บกวาดและเวลาทำงาน BossZY27 เป็นผู้ประสานรายการและตรวจผลจากหน้าเว็บ; ณ เวลาบันทึกยังไม่มีชื่อผู้ดำเนินการที่ทีมยืนยัน จึงยังไม่อ้างว่ามีข้อตกลงหรือลบข้อมูลแล้ว การทดสอบ Admin ปฏิเสธรีวิว ID 4 ข้างต้นเกิดขึ้นก่อนข้อตกลงนี้ และการสร้างบัญชี ID 15 กับ Provider ชั่วคราว ID 14 ตามคำขอให้ตรวจโฟลก็เกิดก่อนยืนยันผู้ดูแล Neon เช่นกัน ต้องบันทึกทั้งสองช่วงเป็นข้อยกเว้นของกระบวนการทดสอบ ไม่ย้อนเขียนว่ามีแผนลบก่อนทดสอบ Provider ID 14 ถูกลบผ่าน UI แล้ว แต่ audit history ยังอยู่ หลังจากนี้งดสร้างข้อมูล UAT เพิ่มจนกว่าทีมจะตกลงผู้รับผิดชอบและวิธีเก็บกวาด

รายการที่ต้องตรวจและเก็บกวาดคือบัญชี UAT ID 8/9/10/15, Provider ID 7 และรีวิว ID 4/5 เท่านั้น บัญชี ID 15 เพิ่มในรอบ bookmark ข้างต้น โดยลบ bookmark ที่ใช้ทดสอบแล้ว รีวิวทั้งสองอยู่สถานะ `REJECTED` จึงไม่ขึ้นหน้าเว็บสาธารณะ แต่ยังเป็นข้อมูลค้างในฐาน ก่อนลบให้ผู้ดูแล Neon ทำ backup ตาม [Task 24](task24-backup-restore.md) และตรวจ ID, ผู้สร้าง, ความสัมพันธ์กับคอร์ส/Provider และจำนวนแถวในฐานจริงอีกครั้ง ผลหน้า Admin Audit Log ข้างต้นพบ actor ID 8/9 มี audit history และเหตุรับรอง Provider 7 เป็น actor ID 1; ตาราง `audit_logs` ใช้ `ON DELETE RESTRICT` กับผู้กระทำ จึงห้ามลบบัญชีแบบฝืน foreign key หรือสั่งลบ audit history โดยไม่ตกลงแนวทางเก็บหลักฐานกับทีม ผลจาก UI ยังไม่แทนการตรวจความสัมพันธ์ในฐานจริงและการยืนยันผู้รับผิดชอบ Neon

เมื่อทีมยืนยันรายการและวิธีจัดการ audit แล้ว ให้ผู้ดูแล Neon ลบเฉพาะข้อมูล UAT ภายใน transaction โดยจัดการรีวิวและข้อมูลลูกก่อน Provider/บัญชี ตรวจจำนวนแถวที่ลบกับรายการที่อนุมัติ และ rollback ถ้าพบข้อมูลอื่นปะปน หลัง commit ให้ BossZY27 ตรวจว่าบัญชีทดสอบเข้าไม่ได้, Provider/รีวิวทดสอบไม่อยู่ในหน้าจัดการ และ catalog/รีวิวจริงยังเหมือนเดิม เก็บเฉพาะเวลา ผู้ดำเนินการ และจำนวนแถวในรายงาน ห้ามบันทึกรหัสผ่าน, cookie หรือ backup ฐานข้อมูลใน repo

## งาน UAT ที่ยังต้องตรวจ

- ทดสอบ Admin ปฏิเสธรีวิว UAT บน production แล้ว; โฟลรับรอง Provider, ส่งตรวจ/เผยแพร่คอร์ส และอนุมัติรีวิวบน production ยังต้องใช้ข้อมูลทดสอบที่ทีมยืนยันให้เปลี่ยนสถานะได้ โฟลเหล่านี้ผ่านใน E2E บนฐานข้อมูลแยก

- ยืนยันผู้ดูแล Neon และวิธีจัดการ audit history ตามแผนเก็บกวาดด้านบนก่อนลบข้อมูล UAT; รีวิว ID 4 และ ID 5 ถูกปฏิเสธแล้ว แต่ยังอยู่ในฐานข้อมูล

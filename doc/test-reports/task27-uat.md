## บัญชี UAT บน production — 10 ตุลาคม 2026

หลังได้รับอนุญาตจากผู้รับผิดชอบงาน สร้างบัญชีทดสอบ 3 บัญชีผ่าน `https://group36-coursehub.vercel.app/`: ผู้เรียน (user ID 8), เจ้าของ Provider (user ID 9) และบัญชีตรวจฟอร์มสมัครหน้าเว็บ (user ID 10) ทั้งหมดมี role `LEARNER` ตามระบบปัจจุบัน บัญชีที่สองสร้าง Provider ทดสอบ ID 7 ซึ่งตอนสร้างมีสถานะ `PENDING` และเห็นรายการนี้ผ่าน `/api/v1/providers/me` ส่วนบัญชีผู้เรียนไม่เห็น Provider ของอีกคน ต่อมามีการรับรอง Provider ทดสอบนี้แล้ว รอบตรวจล่าสุดเห็นสถานะ `ACTIVE`

สองบัญชีแรก login ตอบ 200, `/api/v1/me` ระบุบัญชีถูกต้อง, endpoint admin ตอบ 403, logout ตอบ 204 และ `/api/v1/me` หลัง logout ตอบ 401; session cookie มี `Secure`, `HttpOnly` และ `SameSite=Lax` ไม่บันทึกรหัสผ่านหรือค่า cookie ใน repo หลักฐานรหัสอยู่ในไฟล์ส่วนตัวบนเครื่องผู้รับผิดชอบงาน บัญชีและ Provider ทดสอบยังคงอยู่สำหรับ UAT รอบถัดไป การลบ Provider ทำได้ผ่าน API โดยเจ้าของ แต่การลบบัญชีต้องประสานผู้ดูแลฐานข้อมูล เพราะยังไม่มี endpoint ลบบัญชี

## UAT โฟลผู้เรียนและ Provider ที่ไม่ต้องใช้ Admin บนเว็บจริง — 10 ตุลาคม 2026

| โฟล | ผล |
| --- | --- |
| ผู้เยี่ยมชมเข้าหน้า protected, กรอกรหัสผ่านผิด | ถูกส่งไปหน้า login; รหัสผิดตอบ 401 และแสดงข้อผิดพลาด |
| สมัครผ่าน UI, login, refresh, logout, login ใหม่ | ผ่าน; session ยังอยู่หลัง refresh และหมดหลัง logout |
| โปรไฟล์ผู้เรียน | อ่าน, แก้, โหลดกลับ และคืนค่าเดิมผ่าน |
| ค้นหา/กรองคอร์ส, matcher | ค้นหาและกรองภาษาได้; matcher แสดงทั้งผลที่พบและกรณีไม่พบ พร้อมกลับไปแก้คำตอบ |
| Bookmark | บันทึก, แสดงรายการ และลบผ่าน; อีกบัญชีมองไม่เห็น bookmark ของผู้เรียน |
| รีวิว | สร้างผ่าน UI, แก้ผ่าน UI/API ผ่าน; รีวิวใหม่เป็น `PENDING` และไม่ปรากฏในรายการสาธารณะ |
| Provider | สร้าง/แก้/ลบ Provider ชั่วคราวผ่าน UI; Provider หลัก ID 7 ยัง `PENDING` |
| สมาชิก Provider | Owner เพิ่ม Editor, Editor เห็นและแก้คอร์สร่างได้ แต่จัดการสมาชิกไม่ได้; เมื่อลบ Editor แล้วถูกปฏิเสธอีกครั้ง |
| คอร์สของ Provider | สร้าง/แก้/ลบ Draft ผ่าน UI/API; Draft ไม่ขึ้น catalog; ส่งตรวจถูกปฏิเสธ 409 เพราะ Provider ยังไม่ `ACTIVE` |

หลังทดสอบคืนค่าโปรไฟล์และลบ bookmark, Editor ชั่วคราว, คอร์สร่าง และ Provider ชั่วคราวแล้ว ตรวจซ้ำว่า Provider หลักไม่มีคอร์สและเหลือ Owner คนเดียว ข้อมูลที่ยังคงไว้สำหรับ UAT ต่อคือบัญชี 3 บัญชี, Provider ID 7 และรีวิว ID 4/5 บนคอร์ส ID 6 (มีข้อความระบุว่าเป็น UAT และห้ามอนุมัติ) ปัจจุบันรีวิวทั้งสองถูกปฏิเสธแล้ว ระบบไม่มี API ลบรีวิวหรือบัญชี จึงต้องให้ผู้ดูแลฐานข้อมูลจัดการเมื่องานจบ ไม่เผยแพร่รหัสผ่านหรือ cookie ในรายงาน

## ตรวจเว็บจริงเพิ่ม — 10 ตุลาคม 2026

| โฟล | ผล |
| --- | --- |
| ผู้เยี่ยมชมดู catalog และค้นหา UI/UX | พบคอร์สที่เผยแพร่ 6 รายการ; ค้นหา UI/UX ได้ 1 รายการ |
| ผู้เยี่ยมชมทำ matcher | ตอบ UI/UX, เริ่มต้น, ภาษาไทย, งบ 2,000 บาท และ 10 ชม./สัปดาห์; ได้คอร์ส UI/UX Design Masterclass พร้อมเหตุผลประกอบ |
| Admin เข้าสู่ระบบและเปิดหน้างานตรวจ | ผ่าน; เห็น Provider ที่รอตรวจและรีวิวที่รอตรวจ |
| Admin ปฏิเสธรีวิว UAT ID 4 | ผ่าน; บันทึกเหตุผลว่าเป็นรีวิวทดสอบ และเมื่อเปิดตัวกรองอีกครั้งสถานะเป็น `REJECTED` พร้อมเหตุผล; ไม่อนุมัติรีวิวทดสอบหรือเปลี่ยนสถานะ Provider ของผู้อื่น |
| Admin refresh, ออกจากระบบ, ผู้เยี่ยมชมเปิด `/admin` | Session Admin ยังอยู่หลัง refresh; logout กลับหน้า login; ผู้เยี่ยมชมถูกส่งไป login |
| Admin เปิดหน้ารีวิวคอร์ส | อ่านรีวิวได้ แต่ไม่มีฟอร์มเขียนรีวิวสำหรับ role Admin |

การเปิดหน้า login และการ refresh หน้า Admin แสดง “กำลังเตรียมระบบ…” ชั่วครู่ก่อนใช้งานต่อได้ ยังไม่มีหลักฐานเพียงพอจะสรุปว่า Render หลับหรือใช้เวลากี่วินาที รอบนี้ไม่ได้ล็อกอินซ้ำด้วยบัญชีผู้เรียน/Provider ที่สร้างไว้ก่อน จึงไม่อ้างว่าทดสอบโฟลเขียนข้อมูลของสองบทบาทนั้นซ้ำบน production

## งาน UAT ที่ยังต้องตรวจ

- ทดสอบ Admin ปฏิเสธรีวิว UAT บน production แล้ว; โฟลรับรอง Provider, ส่งตรวจ/เผยแพร่คอร์ส และอนุมัติรีวิวบน production ยังต้องใช้ข้อมูลทดสอบที่ทีมยืนยันให้เปลี่ยนสถานะได้ โฟลเหล่านี้ผ่านใน E2E บนฐานข้อมูลแยก
- ตรวจ bookmark หลังรีเฟรชหน้าเว็บซ้ำ: รอบตรวจเพิ่มหน้า login โหลดค้าง จึงยังไม่บันทึกว่าเคสนี้ผ่าน ตอนนั้นไม่ได้เก็บเวลา ภาพหน้าจอ หรือ Network request และไม่ได้บันทึกว่าหน้าเว็บขึ้น “กำลังเตรียมระบบ…” หรือ “ลองใหม่” หรือไม่ จึงยังสรุปไม่ได้ว่าเกิดจาก Render ตื่นช้าหรือเป็นบั๊กของหน้าเว็บ ต้องทำซ้ำพร้อมบันทึกเวลา ขั้นตอน สถานะหน้าจอ และ request ที่ค้าง
- ตกลงวิธีลบบัญชีและรีวิว UAT ที่คงไว้หลังตรวจ Admin เสร็จ; รีวิว ID 4 และ ID 5 ถูกปฏิเสธแล้ว แต่ยังอยู่ในฐานข้อมูล
- พฤติกรรมหน้าเว็บระหว่าง Render Free หลับและตื่น, รวมถึงการกด “ลองใหม่”: [Task 25](task25-deployment.md#checks-on-the-public-site) เคยพบ Render ตื่นช้าและหน้าเว็บแสดงสถานะกำลังโหลดแล้ว แต่ UAT รอบนี้ backend ตอบทัน จึงยังไม่ได้ตรวจปุ่ม “ลองใหม่” และการฟื้นตัวจาก cold start บน production แบบครบโฟล
- ตรวจร่วมกับทีมว่า `group36-coursehub.vercel.app` เป็นโดเมนหลักสำหรับส่งงานหรือไม่ แล้วค่อยปิดรายการ UAT ก่อน release เข้า `main`

# คู่มือดูประวัติการใช้งานระบบ (UC19)

## เข้าใช้งาน

เปิดแอปด้วยบัญชี Admin ที่ยัง active แล้วเลือกเมนู **ประวัติระบบ** หรือเปิด `/admin/audit-logs` โดยตรง ผู้ใช้ทั่วไปจะไม่เห็นเมนูและเข้า route ไม่ได้ API `GET /api/v1/admin/audit-logs` ตรวจทั้ง session และบทบาท Admin ปัจจุบันในฐานข้อมูล ไม่มี API สำหรับแก้หรือลบประวัติ

หน้าเว็บแสดงเวลาท้องถิ่นพร้อมชื่อ timezone ที่ใช้แสดง แต่ API ส่งเวลาเป็น UTC ข้อมูลแต่ละรายการมีผู้กระทำและ ID, กิจกรรมพร้อมรหัสเดิม, ประเภทและ ID ของรายการ, สถานะก่อน/หลัง และเหตุผล ค่าไม่มีข้อมูลจะแสดง `—` หากบัญชีผู้กระทำไม่มี profile ระบบใช้ชื่อ `ผู้ใช้ #<ID>` ประวัติของคอร์ส/Provider/สมาชิกที่ถูกลบแล้วยังอ่านได้จาก ID ที่บันทึกไว้

## ค้นหาและแบ่งหน้า

เลือกประเภทข้อมูลหรือกิจกรรม กรอก ID ผู้กระทำ/รายการ และกำหนดช่วงเวลาได้ ตัวกรองใช้ร่วมกันได้ เวลาที่กรอกเป็นเวลาท้องถิ่นของเบราว์เซอร์; หน้าเว็บแปลงเป็น UTC ก่อนส่ง API ช่วงเวลารวมจุดเริ่มต้น แต่ไม่รวมจุดสิ้นสุด (`from <= createdAt < to`) กด **ค้นหา** เพื่อใช้ตัวกรอง หรือ **ล้างตัวกรอง** เพื่อดูทั้งหมด การค้นหาใหม่เริ่มหน้าแรก ปุ่มหน้าก่อน/หน้าถัดไปใช้ pagination จากเซิร์ฟเวอร์ หน้าละ 10 รายการ เรียงเวลาใหม่สุดก่อน และใช้ ID มากสุดก่อนเมื่อเวลาเท่ากัน

เมื่อโหลดไม่ได้ กด **ลองใหม่** หาก session หมดอายุ ให้เข้าสู่ระบบอีกครั้ง รายการว่างจะแสดงข้อความว่าไม่พบประวัติ การแสดงเหตุผลเป็นข้อความปกติ ไม่แปลเป็น HTML

## ใช้ API โดยตรง

ตัวอย่าง: `GET /api/v1/admin/audit-logs?entityType=COURSE&action=COURSE_APPROVE&actorId=1&entityId=12&from=2026-01-01T00%3A00%3A00Z&to=2026-02-01T00%3A00%3A00Z&page=0&size=10`

`entityType` รองรับ `COURSE`, `PROVIDER`, `PROVIDER_MEMBER`, `REVIEW`; `action` ใช้รหัสกิจกรรมที่บันทึกจริงตาม [API contract](api-contract.md) หน้าเริ่ม 0 ขนาดเริ่ม 10 และสูงสุด 50 ID ต้องเป็นจำนวนบวก ช่วงเวลาต้องเป็น ISO-8601 UTC และ `from < to` คำขอผิดตอบ `400` ตาม error contract เดิม

## การรันและตรวจสอบ

เริ่มระบบตาม [README](../README.md) โดยมี PostgreSQL และ Flyway จากนั้นเข้าสู่ระบบ Admin บนเว็บ สร้างกิจกรรมผ่านหน้า Provider/คอร์ส/รีวิว แล้วเปิดประวัติ ข้อมูลที่แสดงอ่านจากตาราง `audit_logs` จริง ไม่ต้องสร้าง migration ใหม่สำหรับ UC19 ดู [รายงานการทดสอบ](test-reports/audit-log.md) สำหรับคำสั่งและหลักฐาน

การเขียน Audit Log ใน transaction และ Observer metrics เป็นงานเดิม แยกอธิบายใน [คู่มือ Task 17](task17-audit-observer-guide.md)
